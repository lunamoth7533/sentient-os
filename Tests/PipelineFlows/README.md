# Pipeline flow regressions

Run `/opt/homebrew/bin/python3 Tests/PipelineFlows/run.py` on macOS. Each named Python runner also runs independently from any working directory. `SWIFT_BIN` and `SDKROOT` override the default verified Xcode-beta Swift toolchain and macOS 27 SDK.

These checks compile the current production source at run time. They do not use copied implementations. No runner launches Sentient, loads a model, connects to a cloud service, modifies production preferences, or reads configured user sources.

- `controller.py`: real SQLite store, importers, projections, and `ContextLibrary` in a temporary directory. Covers concurrent callers, sharing off, immediate source exclusion, projection failure and retry, active-source cancellation, and original-file preservation.
- `processing.py`: actual `ProcessingView` run methods in a minimal state holder, with artificial model and cloud dependencies. Covers imported-only operation, import/device/Gmail/Calendar failures, onboarding isolation, and successful sequencing. Its class wrapper adds explicit closure captures required when running SwiftUI's value-type methods in a class.
- `scheduler.py`: actual scheduler flow with artificial preferences, source selections, wake helper, model, cloud legs, and logging. Covers imported-only operation, import/device/cloud/tail failures, cancellation cleanup, and completion after cleanup. The preference substitution is checked before execution.
- `proactive.py`: actual proactive actor with an artificial summary store and cloud stages. Covers strict read and cleanup failure, cancellation after best-effort stages, cancellation on entry, and clean completion. Native SwiftData cleanup and snapshot preservation are separately tested by `Tests/LegacyReliability`.
- `commands.py`: actual `CommandRunModel` and `AgentStatus` with artificial capture, persisted-permission reads, detached retrieval, and model responses. Covers capture/retrieval cancellation, visible and transient private windows, source sharing revocation/exclusion/removal, failed permission validation, shared-source filtering, and honest completion outcomes. It never runs Codex.
- `capture.py`: actual `ScreenCapture` capture loop with injected permission and acquisition boundaries. All frame files contain synthetic text. Covers transient protected windows, revocation and cancellation cleanup, partial-display failure, and normal cleanup. A transparent, offscreen synthetic AppKit window verifies the actual visibility marker through show, hide, close, and reuse. It does not run `screencapture`, inspect screen pixels, or request permission.
- `status.py`: actual final-status parser. Covers exact final sentinels, negative/extended tokens, quoted or fenced examples, earlier statuses followed by failure, safe legacy refusal, and reason preservation.
- `streams.py`: extracts the current `CodexCLI` stream accumulators, process runner, and `runAgentCommand` return selection, then uses real pipes from an isolated Python child emitting only artificial text. Covers valid completion/refusal with a later stderr usage trailer, empty or unconfirmed stdout, and a final message without a newline. The child never invokes Codex and receives an empty environment. The representative stream split follows the verified [Codex 0.153.4 output implementation](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/exec/src/event_processor_with_human_output.rs#L375-L397): usage is on stderr and the final message is on stdout for piped execution.

There are 7 processing, 7 scheduler, 6 proactive, 16 command, 15 capture, 18 status, and 5 stream checks, plus the controller lifecycle assertions. These are regression checks for orchestration, privacy, and data preservation; they complement the full Xcode build and UI smoke tests. Existing scheduler actor-isolation warnings under Swift 5 do not indicate failed assertions.
